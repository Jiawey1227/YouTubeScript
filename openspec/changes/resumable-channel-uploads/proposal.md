## Why

本地视频要传到多个 YouTube 频道，但浏览器或电脑会意外关闭、自动重启。上传进度停在内存里时，无法知道每个文件传到了哪个频道、是否已经发布，重启后也无法从断点继续。

## What Changes

- 新增一个本机上传程序，与现有「剧名查播」扩展分开。扩展的搜索、控制页和“关闭后不恢复任务”行为保持不变。
- 每个目标频道在本机授权一次。刷新令牌只保存在本机，不进入仓库。
- 用户把本地视频文件加入某个已授权频道的队列。任务在接受时立即写入磁盘，记录文件、频道、状态、已确认字节、续传地址和视频 ID。
- 程序使用 YouTube 官方可续传上传。进程或电脑重新启动后先读账本：续传地址仍有效则查询已收到的字节并继续；地址过期则先核对频道里是否已有该任务对应的视频，已有就记为完成，没有才重新开始。
- 未写明的默认：标题取文件名（去掉扩展名），公开范围为不公开；同一时间只上传一个文件；不做封面、定时发布、播放列表或开机自启。用户重新启动程序后才会继续未完成任务。
- 同一个 Google Cloud 项目下，新开始的上传共用每天 100 次的默认额度。沿用未过期的续传地址不另占一次。额度用尽时任务保持可恢复，不把文件标成永久失败。

## Capabilities

### New Capabilities

- `channel-connection`: 在本机连接、列出和断开多个 YouTube 频道的授权。
- `upload-job-ledger`: 把每个上传任务持久化，并在关闭或重启后显示其最新状态。
- `resumable-channel-upload`: 按官方可续传协议上传，启动时对账，并避免把同一任务发布成第二个视频。

### Modified Capabilities

无。`manual-drama-entry` 与 `youtube-title-search` 的要求不变。

## Impact

- 新增独立于扩展后台的本机程序、本地状态目录、状态页，以及对应测试和说明。`src/` 中的搜索流程、`manifest.json` 与现有规格不改。
- 依赖用户自己的 Google Cloud OAuth 客户端和 YouTube Data API 可续传上传。令牌、客户端密钥和任务账本留在本机并被忽略，不提交。
- 状态页只读取账本；关掉状态页不影响正在进行的上传。
