## Context

扩展现在每次从控制页开始搜索都会新开一个 YouTube 标签，同一轮里的多个剧名才复用它。后台在控制页断开时清除任务。标题匹配和搜索卡片播放量原文已经存在。动机见 proposal.md。

## Goals / Non-Goals

**Goals:**

- 脚本拥有文件夹、清单、播放量解析和废纸篓。扩展只领取一部剧、搜索并交回三种明确结果。
- 脚本搜索跨剧复用一个 `active: false` 的标签，并把标签 id 存进扩展本地，服务工作线程重启后仍能找回。
- 手工搜索继续每轮新开标签。脚本标签和用户自己的 YouTube 标签都不被关闭。

**Non-Goals:**

- 不把 Chrome 原生消息当作脚本发起连接的方式。原生消息只能由扩展把程序拉起来，不能由已经在跑的脚本反向呼叫扩展。
- 不改标题匹配、20 个剧名上限，也不把脚本结果写进控制页结果表。
- 不扫描脚本启动前已经在文件夹里的文件。

## Decisions

### 1. 脚本监听本机端口，扩展定时来取

脚本监听 `127.0.0.1:17321`。扩展用闹钟大约每 30 秒询问一次，询问中带上「是否正在手工搜索」和「是否已有脚本搜索未返回」。脚本据此回答剧名，或回答现在没有。替代方案是原生消息：Chrome 会另起一个程序，和「用户启动并停止脚本」冲突。

### 2. 清单和锁分开

`.drama-watch.json` 保存未完成队列和已查完记录。`.drama-watch.lock` 只表示进程占用，写入进程号；进程不在时下一个脚本可以接管。两个文件都以点开头，因此不会被当成剧。文件身份使用 inode 和 `birthtimeMs`。废纸篓使用系统「移到废纸篓」的能力，不用直接删除。

### 3. 脚本搜索不走控制页断开清理

脚本任务在控制页关闭时保留。控制页断开只取消带有手工来源的任务。脚本标签 id 单独保存，不拿手工搜索留下的标签来复用。

### 4. 播放量解析留在脚本

扩展交回匹配视频的播放量原文。脚本按规格换算并和阈值比较。这样扩展不把「1.2万」改写成精确整数。

## Risks / Trade-offs

- [「1.2万」按 12000 比较，真实值可能略低或略高] → 按已确认的换算执行，终端写明采用的数字和阈值。
- [验证码、超时和同意页记成搜索失败后不再重试] → 文件留在原处，清单写明扩展返回的原因。
- [启动前已在文件夹里的文件永远不查] → 只处理启动后新进来的文件；未完成项在重启后例外。
- [扩展大约 30 秒才来取一次] → 新文件最多因此多等一个询问周期。
- [读不到创建时间时只认 inode] → 避免把已查完文件再次移走；新文件若复用了 inode，可能被跳过。

## Migration Plan

重新构建并在 Chrome 中加载扩展。用户启动脚本时传入文件夹和阈值，再打开控制页开关。回退时关掉开关并停止脚本，恢复上一版扩展。清单文件可留在监视文件夹里。
