## Context

项目暂无应用实现，动机与范围见 proposal.md。本次涉及导入、网页适配、任务持久化和导出多个模块，需建立首版架构。网页提取尚未进行真实验证，之前 API 网络测试的失败不能用来判断用户浏览器是否能够访问 YouTube。

## Goals / Non-Goals

**Goals:**
- 将网页解析与匹配规则、任务调度分离，网页变化时可以单独修复适配器。
- 任务不依赖弹出窗口或后台进程持续存活，数据能够从检查点恢复。
- 在个人 Chrome 中本地加载并验证，不需要服务器或密钥。

**Non-Goals:**
- 不实现跨设备同步、无人值守定时执行或 Chrome 商店发布流程。
- 不保证搜索结果跨账号、时间和地区一致，不宣称覆盖全站。

## Decisions

### 1. 插件结构与工具链

采用 Manifest V3、TypeScript 和原生 HTML/CSS 控制页。点击插件按钮打开独立扩展页面，避免长表格和导入流程受 popup 关闭影响。计划采用 Vite 构建、Vitest 测试、ESLint 与 Prettier；实施时固定可用版本并提交锁文件，构建运行时固定 Node.js 22。不引入 React 等 UI 框架，当前交互规模无需额外组件运行时。页面样本测试使用轻量服务端 DOM 实现 Domino，真实页面行为另由用户验收。

源码放在 src/，测试与去标识页面样本放在 tests/，必要的验证记录放在 docs/，构建产物 dist/ 不提交。README 与 AGENTS.md 在实现阶段更新实际命令及布局。

### 2. 单标签页与持久任务状态机

控制页负责导入和展示；后台 service worker 处理调度和存储；content script 负责页面就绪检测和提取。仅导航专用采集标签页，不修改用户已有页面。候选与详情均串行查询，导航间默认至少间隔 1 秒；页面读取预算 30 秒，普通超时最多重试一次，不承诺实际每剧耗时。

任务状态为 idle、running、paused、waiting-user、completed；单剧状态区分 pending、searching、collecting、done、partial、failed。后台每个步骤保存下一动作、候选快照、已处理视频及结果，不依赖全程循环或内存计数。事件或闹钟触发检查点推进，进程重新启动时检查租约和过期动作；浏览器重启后等待用户点击继续。

后台可能休眠的依据见 [Chrome service worker 生命周期文档](https://developer.chrome.com/docs/extensions/develop/concepts/service-workers/lifecycle)。短间隔调度不能依赖闹钟精确到秒；闹钟用于过期检查与唤醒兜底，下一动作启动前重新核对保存的最早执行时间。

以任务 ID、步骤 ID 和视频 ID 校验回传，忽略旧导航、重复及已清除任务的消息。存储写入由后台串行处理；同剧视频用复合键更新，跨剧允许同一视频分别关联。标签页被关闭或手动导航离开预期 URL 时暂停，继续时重建或复用专用页。

使用 IndexedDB 保存任务和结果，避免把整个批次反复写成一个对象；无存储空间时停止并提示导出已有数据。替代方案是把队列全部放在控制页内存中，但无法可靠应对关闭界面和中断。

### 3. 页面采集适配器

限定桌面 www.youtube.com 搜索页与 watch 页面。搜索使用完整剧名 URL 编码且不附加时长或日期预筛选，以保持“先取前十再筛选”语义。按页面出现顺序收集不同普通视频 ID；跳过广告、频道、播放列表和 Shorts 专区，普通结果中的直播候选仍占排名但不入选。最多观察 30 秒并做 3 次有界滚动以获取前十条；不足时区分正常结束、加载受限及页面无法识别，保留实际检查数量。

详情提取优先使用页面内绑定当前视频的结构化元数据，再用明确的 DOM 字段补充。不调用未公开的远程接口，不凭页面全局第一段数字推断播放量。不依赖一个未经验证的内部全局变量；若需要 MAIN world 辅助读取，仅返回经过字段筛选的数据，并校验 videoId 与当前 URL。

匹配采用首尾去空白后的连续子串，大小写敏感、不做繁简转换。时长统一为秒，门槛严格为 >3600；未知时长只补查前十内的候选详情。若详情标题或时长与搜索卡片不同，以详情值重新筛选。

日期只在绝对日期可验证时输出 ISO 日期，若来源提供时间则保留时区。完整播放量归一化为十进制整数字符串，避免不必要的数字精度损失；缺失或只有简写时输出空值和原因。不得用上传日期字段静默替代无法确认的发布日期。保留字段来源及解析状态用于排查。

### 4. CSV 与数据表示

用成熟 CSV 解析库（计划 Papa Parse）处理引号、换行和 BOM，不自行按逗号拆行。导入预览中默认有表头，用户可切换无表头并选择列；这属于未指定的交互细节默认值，不要求固定列名。仅支持 UTF-8，其他编码提示转换。

Job 保存版本、状态、名单、游标、动作和时间；Drama 保存搜索状态、候选数、范围是否完整和错误；VideoResult 保存剧名、rank、videoId、title、durationSeconds、publishedAt、viewCount、collectedAt、字段状态及来源。列表用分页展示，导出不受当前页限制。结果为本次采集快照，无需历史趋势模型。

### 5. 权限与验证边界

权限计划限定为 storage、scripting、alarms 及 https://www.youtube.com/* 主机权限；实施时逐项核对用途，不申请全站或 cookies 权限。通过扩展页 Blob 下载 CSV，避免无必要的下载管理权限。所有依赖打包到插件中，不加载远程代码。CSV 和网页文本作为纯文本渲染，导出时处理公式前缀。

测试分为规则单测、静态页面样本解析、带模拟浏览器接口的调度测试和真实 Chrome 手工验收。实施初期先用 5～10 个剧名核实网页字段和耗时；若无法可靠取得字段，记录明确缺失，不把自动化样本测试作为真实页面可用的证据。

## Risks / Trade-offs

- [页面结构与语言变化] → 适配器隔离、中文和英文页面样本、解析失败可见；真实页面验证是交付检查项。
- [后台休眠、标签页中断和迟到回传] → 检查点、幂等写入、消息身份校验、显式恢复。
- [验证码或登录阻塞] → 暂停等待用户处理，不循环刷新或绕过。
- [个性化结果与有限样本] → 显示采集时间和实际检查范围，不将无匹配表述为全站无视频。
- [页面仅给近似数据] → 留空并标记缺失，准确率优先于表格填满。
- [首版吞吐量未知] → 真实测量每剧耗时、每次详情访问数量和失败率；不按未经测试的秒数限制 CSV 行数。

## Migration Plan

无需旧数据迁移。实现后构建 dist/，用户通过 Chrome 开发者模式加载未打包扩展；先执行少量剧名验收，再使用完整 CSV。持久数据带版本号，遇不兼容版本停止恢复并提示导出或清除。回退时停用扩展并保留已导出 CSV，不改动 YouTube 账号数据。

## Open Questions

- 当前中英文页面最可靠的精确日期与播放量字段位置，需要实施初期实测确定；字段缺失行为已由规格固定。
- 单剧平均耗时、后台标签页节流影响及推荐批量规模，需要真实运行记录确定，不影响前十条上限。
