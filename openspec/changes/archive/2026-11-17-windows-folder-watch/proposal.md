## Why

文件夹监视脚本现在只适用于 macOS：它把文件移到 `~/.Trash`，在 Windows 上没有这个目录，播放量达标后移动会一直失败。用户实际要在 Windows 上运行整套功能，并且需要同时监视多个文件夹，把达标文件集中到一个指定的输出文件夹。

## What Changes

- 平台范围改为只支持 Windows 10 及以上。脚本 MUST 在 Windows 上运行；在 macOS 或 Linux 上启动时说明不支持并退出，不建立清单。
- **BREAKING**：达标文件不再移到系统回收站，改为移动到启动时指定的输出文件夹。不删除文件，同名时用带序号的新名字保存，不覆盖已有文件。
- 启动参数改为：一个或多个来源文件夹、一个输出文件夹、一个共用的播放量阈值。一个脚本进程监视全部来源文件夹，使用同一个端口。
- 「隐藏文件」按 Windows 的定义判断：除了点开头的名字，带隐藏或系统属性的文件也算隐藏，`desktop.ini`、`Thumbs.db`、`$RECYCLE.BIN` 不会被当成剧名。
- 文件身份在系统不提供可用文件编号时，改用规范化路径加创建时间，避免把不同文件当成同一个。
- 提供 `.cmd` 启动文件，一次传入全部文件夹和阈值。
- 浏览器扩展本身不改：Manifest V3、`127.0.0.1:17321` 和后台标签在 Windows 的 Chrome 上本来就可用，也不需要知道有几个来源文件夹。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `folder-drama-watch`: 平台限定为 Windows；支持多个来源文件夹共用一个进程和端口；达标文件移到指定输出文件夹而不是回收站；隐藏文件和文件身份按 Windows 处理；单实例占用覆盖输出文件夹和全部来源文件夹。

## Impact

- `src/watch/` 的废纸篓、文件枚举、队列、清单和参数解析需要改写，并新增 `.cmd` 启动文件。
- `README.md`、`docs/acceptance.md`、`docs/validation.md` 中关于 macOS 路径、`~/.Trash` 和单个文件夹的说明要改掉。
- 不影响剧名匹配、播放量解析、控制页、扩展权限和本机端口协议。
