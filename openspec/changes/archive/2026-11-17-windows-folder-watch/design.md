## Context

文件夹监视脚本已经实现，但 `src/watch/trash.ts` 把文件移动到 `homedir()/.Trash`，这是 macOS 的路径。Windows 没有这个目录，移动会抛错，脚本按规则把状态留在移动失败上一直重试。文件枚举、清单身份和隐藏文件判断也按 macOS 写的，队列和清单只支持一个文件夹。动机见 proposal.md。

## Goals / Non-Goals

**Goals:**

- 在 Windows 10 及以上跑通：多来源文件夹、单进程单端口、共用一个阈值、达标文件移到指定输出文件夹。
- 输出文件夹同名冲突时用带序号的名字保存，绝不覆盖、绝不删除。
- 提供一个 `.cmd` 启动文件，一次传入全部文件夹和阈值。

**Non-Goals:**

- 不继续支持 macOS 或 Linux。
- 不改扩展本身，也不改剧名匹配、播放量解析、端口协议和已查完状态的六种分类名称。
- 不做移动前按剧名分目录、不做改名、不做开机自启或图形界面。

## Decisions

### 1. 队列和清单按来源文件夹区分

未完成项除了文件身份和路径，还要记来源文件夹。清单仍只是一个文件，放在输出文件夹里。多个来源文件夹共用一个发现顺序，避免每个文件夹各自排序后互相插队。

替代方案是每个来源文件夹一个清单。那会让重启后的顺序取决于读取顺序，且同一部剧可能被两份清单各查一次。

### 2. 平台检查放在最前

启动时先检查 `process.platform === 'win32'`，不是就直接退出，不建清单、不占端口。这样在 macOS 上误启动时不会留下只属于 Windows 的清单文件。

替代方案是自动判断平台再选实现。用户已明确只支持 Windows，保留 macOS 分支只会让两边都缺乏验证。

### 3. 移到输出文件夹用 rename，跨卷时复制后删除源文件

同一卷上直接 `rename`。`EXDEV` 表示输出文件夹在另一个卷，此时复制到目标名字、确认复制成功后再删除源文件。目标已存在时改用 `名字 (2).ext`、`名字 (3).ext` 这样的序号，直到找到空位。

替代方案是调用 PowerShell 的回收站接口。用户已改为移动到指定文件夹，回收站那套不再需要。

### 4. 隐藏文件包括系统属性

枚举条目时一并读取隐藏和系统属性，带这些属性的等同于隐藏，`desktop.ini`、`Thumbs.db`、`$RECYCLE.BIN` 都跳过。

### 5. 文件身份带回退

优先用 `ino` 加 `birthtimeMs`。`ino` 为 0 或 `birthtimeMs` 不是有限值时，改用 `path.toLowerCase()` 加 `birthtimeMs`。Windows 路径大小写不敏感，比较前统一转小写。旧清单读到没有身份标记的记录时按 `ino` 处理，不因此丢掉未完成项。

### 6. 锁覆盖输出文件夹和全部来源文件夹

输出文件夹用 `.drama-watch.lock`，每个来源文件夹各写一个占用文件。任何一个已被存活的进程占用就退出，避免两个脚本抢同一个来源文件夹。

## Risks / Trade-offs

- [输出文件夹位于来源文件夹内] → 启动时直接拒绝，否则会把移入的文件再次当成新剧。
- [跨卷复制中途失败] → 源文件保留，按移动失败处理，下次重试，不会出现只删了源文件的情况。
- [两个来源文件夹有同名文件] → 输出文件夹里用序号各存一份，不覆盖。
- [`ino` 为 0 的卷上同路径同名文件被覆盖] → 创建时间不同会被当作新文件；创建时间也相同时视为同一文件，不重查。
- [移动后文件回到来源文件夹] → 已查完记录按文件身份识别，不再搜索。

## Migration Plan

在 Windows 上重新 `npm run build`，用 `.cmd` 启动并传入来源文件夹、输出文件夹和阈值。清单格式从只含 inode 的旧记录继续兼容，无需手工迁移。回退时换回上一版 `dist/watch-dramas.js`。
