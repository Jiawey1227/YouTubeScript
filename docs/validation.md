# 验证记录

日期：2026-11-17。当前状态：手动剧名搜索和文件夹监视的自动化检查已完成，真实 Windows、Chrome、YouTube 页面和输出文件夹移动仍由用户验收，尚未标记为通过。

- `npm test`：11 个测试文件、67 项测试通过。页面样本使用 Domino 解析，不启动浏览器。
- `npm run typecheck`：通过。
- `npm run lint`：通过。
- `npm run check`：通过。其中包含格式检查、lint、类型检查、上述测试，以及 Vite 7.3.6 构建。构建生成 `dist/index.html`、`dist/background.js`、`dist/content.js`、`dist/watch-dramas.js`、样式脚本和 `dist/manifest.json`。
- 本机执行检查时使用的是 Node.js 24.19.0。目标运行环境仍是 Node.js 22.12 以上、同一主版本 22。
- 在本机执行 `node dist/watch-dramas.js` 时，脚本打印「这个脚本只支持 Windows 10 及以上。」并以退出码 1 结束，符合平台限制。

## 已覆盖的自动测试

- 最多 20 个剧名、空行不计数、超过 20 个或空白输入被拒绝、重复剧名按行保留。
- 搜索地址使用完整剧名的 URL 编码。
- 标题去掉标点后仍须连续包含剧名文字；空格、`★` 和繁简仍按原文比较。
- 短于 60 分钟的普通视频仍可匹配；播放量和相对时间保持卡片原文，缺失时标为不可用。
- 广告、Shorts 专区、播放列表、频道和重复视频被排除，超过 10 条的匹配仍全部返回。
- 每个剧名只打开搜索页；后一个剧名失败时保留前一个结果，并且不会进入暂停等待。
- 启动时清除已有任务。旧版 IndexedDB 任务被清除，不会继续打开视频详情页。
- 结果表同时展示匹配、没有匹配和失败，网页标题按文本写入。
- Manifest 权限、CSP、无远程脚本、无 `innerHTML`，以及只额外允许 `127.0.0.1:17321`。
- 文件名到剧名、播放量换算（万/亿/k/m、`1.2万` = 12000）、最大值比较和无法解析的区别。
- 平台限定为 Windows；非 Windows 直接拒绝。
- 启动参数：多个来源文件夹、一个输出文件夹、一个阈值；拒绝不存在的来源、非法阈值、输出文件夹是文件、输出文件夹位于来源文件夹之内。
- 多来源文件夹共用一个发现顺序、一个为空时另一个照常、后面的文件夹不越过未稳定的文件。
- 隐藏文件、`desktop.ini`、`Thumbs.db`、点开头名字、子文件夹和符号链接都被跳过。
- 文件身份在有编号时用编号加创建时间，没有时用小写路径加创建时间；旧清单记录仍被识别。
- 同卷 rename 移动、同名序号保存、跨卷复制后删除源文件、复制大小不一致时保留源文件。
- 清单与锁：同一输出文件夹重复启动、两个脚本共用一个来源文件夹、退出时释放。
- 本地端口按队列回答剧名并在收到结果后移动到输出文件夹。
- 脚本搜索和手工搜索的互斥、脚本结果只交一次、复用同一个后台标签。

## 仍需用户验收

验收步骤见 [验收清单](acceptance.md)。真实 Windows 上的 `.cmd` 启动、多来源文件夹、隐藏属性识别、输出文件夹移动，以及真实 YouTube 搜索卡片都尚未在用户环境核对，因此不能标记为通过。自动化测试运行在 macOS 上，Windows 专有分支（隐藏属性查询、输出文件夹实际移动）只验证了拒绝路径和注入的文件操作。

不再把 CSV 导入、前 10 条上限、时长超过 1 小时、视频详情页精确日期或暂停后续跑作为本流程的验收条件。

## 线上页面假设

搜索适配器读取传统 `ytd-video-renderer` 与新版 `yt-lockup-view-model` 普通视频卡片上的标题、播放量文本和相对时间文本。广告、Shorts 专区和播放列表不作为匹配视频。这些假设已由静态样本覆盖，仍需通过用户当前 Chrome 中的 YouTube 搜索页确认。
